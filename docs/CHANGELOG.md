# Objectif

Le fichier CHANGELOG.md contient l'historique officiel des évolutions du projet GH Épaviste.

Il permet de suivre :


• les nouvelles fonctionnalités ;

• les corrections ;

• les améliorations ;

• les changements techniques ;

• les décisions importantes intégrées.


Chaque modification significative doit être enregistrée.


---


# Philosophie

Un projet professionnel doit garder une mémoire claire de son évolution.


Le principe est :


**Document What Changes.**


Une modification non documentée devient difficile à comprendre et à maintenir.


---


# Format des versions


Le projet utilise une organisation par versions.


Format recommandé :


MAJEUR.MINEUR.CORRECTIF


Exemple :


1.4.2


Signification :


MAJEUR :

Changement important d'architecture ou de produit.


MINEUR :

Nouvelle fonctionnalité ou amélioration importante.


CORRECTIF :

Correction de bug ou amélioration technique.


---


# Catégories de modifications


Chaque entrée utilise les catégories suivantes :


## Added

Nouveaux éléments ajoutés.


Exemples :


• nouvelle page ;

• nouveau composant ;

• nouvelle fonctionnalité.


---


## Changed

Modification d'un élément existant.


Exemples :


• amélioration design ;

• changement architecture ;

• optimisation.


---


## Fixed

Correction d'un problème.


Exemples :


• bug ;

• erreur SEO ;

• problème responsive.


---


## Removed

Élément supprimé du projet.


Exemples :


• ancien composant ;

• ancienne fonctionnalité.


---


## Security

Modification liée à la sécurité.


Exemples :


• correction vulnérabilité ;

• amélioration protection.


---


# Règles d'utilisation


Toute modification importante doit être ajoutée.


Obligatoire pour :


□ nouvelles fonctionnalités ;

□ changements architecture ;

□ modifications SEO majeures ;

□ changements sécurité ;

□ changements production.


Facultatif pour :


□ corrections mineures internes ;

□ changements sans impact.

Toute IA travaillant sur GH Épaviste doit :


□ consulter le CHANGELOG avant modification importante ;

---


# Lien avec Git


Le CHANGELOG complète Git.


Git indique :

"Quel fichier a changé ?"


CHANGELOG indique :

"Pourquoi ce changement existe ?"


Les deux doivent rester cohérents.

# Critères de qualité

# Anti-Patterns


❌ écrire uniquement "fix bug" ;

❌ supprimer les anciennes versions ;

❌ oublier les changements importants ;

❌ utiliser le CHANGELOG comme journal personnel.


---


# Validation


Avant chaque Release importante :


✔ CHANGELOG mis à jour.

✔ Version identifiée.

✔ Changements résumés.

✔ Historique conservé.
