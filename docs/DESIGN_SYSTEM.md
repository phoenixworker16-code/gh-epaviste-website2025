# PARTIE 0
# VISION

## Mission

Le Design System est la référence graphique officielle du projet GH Épaviste.

Il garantit que toutes les interfaces développées par des humains ou des assistants IA restent cohérentes, accessibles, professionnelles et évolutives.

Aucun composant ne doit être créé sans respecter ce document.

---

# Philosophie

Le Design System n'est pas un guide graphique.

C'est un système.

Chaque couleur, chaque bouton, chaque espacement, chaque composant possède une raison d'exister.

Le Design System garantit :

la cohérence,

la simplicité,

la performance,

la lisibilité,

la confiance,

la maintenabilité.

---

# Objectifs

Créer une identité forte.

Créer une expérience homogène.

Réduire les incohérences.

Accélérer le développement.

Simplifier les futures évolutions.

Faciliter le travail des assistants IA.

---

# Référence visuelle

Le logo GH Épaviste constitue la source officielle de l'identité visuelle.

Toutes les décisions graphiques doivent respecter :

les couleurs,

les proportions,

l'esprit,

la simplicité,

la personnalité du logo.

Le site doit sembler avoir été construit autour du logo.

Jamais l'inverse.

---

# ADN de la marque

Les assistants IA doivent préserver les valeurs suivantes :

Professionnel

Simple

Rapide

Robuste

Accessible

Moderne

Fiable

Local

Transparent

Humain

---

# Personnalité

GH Épaviste n'est pas :

une startup,

un site futuriste,

un site de luxe,

un site premium extravagant,

un site expérimental.

GH Épaviste est :

un service professionnel,

rapide,

rassurant,

efficace,

orienté conversion.

---

# Inspiration

Le Design System s'inspire des principes de :

Google Material Design

Apple Human Interface Guidelines

Nielsen Norman Group

Baymard Institute

Refactoring UI

Vercel Design

Le style final reste cependant propre à GH Épaviste.

---

# Règle fondamentale

Chaque élément graphique doit répondre à une question simple :

"Aide-t-il réellement l'utilisateur à obtenir un enlèvement d'épave plus rapidement ?"

Si la réponse est non,

l'élément doit être supprimé ou repensé.

---

# Minimalisme

La simplicité prévaut.

Les assistants IA doivent supprimer tout élément décoratif inutile.

Chaque composant doit avoir une fonction.

---

# Priorité

Le Design favorise toujours :

la compréhension,

avant l'esthétique.

La conversion,

avant la décoration.

La lisibilité,

avant les effets visuels.

---

# Mobile First

Le Design est conçu en priorité pour :

Android

↓

iPhone

↓

Tablette

↓

Desktop

Toutes les décisions commencent par le smartphone.

---

# Cohérence

Le visiteur ne doit jamais avoir l'impression de changer de site.

Toutes les pages doivent partager :

la même structure,

les mêmes composants,

les mêmes comportements,

les mêmes espacements,

les mêmes animations,

les mêmes principes.

---

# Gouvernance

Aucun assistant IA ne peut créer :

une nouvelle couleur,

une nouvelle ombre,

un nouveau rayon,

une nouvelle typographie,

un nouveau composant,

sans mettre à jour le présent document.

---

# Objectif long terme

Le Design System doit rester cohérent lorsque le projet passera de 176 pages à plus de 1300 pages.

Chaque nouvelle page devra pouvoir être générée automatiquement tout en conservant exactement la même identité visuelle.

---

# Principe final

Le Design System n'est pas un document.

C'est la source officielle de toutes les décisions graphiques du projet.

Il garantit que GH Épaviste conserve une identité forte, homogène et durable, quels que soient le nombre de pages, les évolutions futures ou les assistants IA participant au développement.

# DESIGN PRINCIPLES
# ==========================================================

## Objectif

Les Design Principles définissent la philosophie qui guide toutes les décisions graphiques du projet.

Ils constituent les règles fondamentales que les assistants IA doivent respecter avant de créer, modifier ou supprimer un composant.

Ces principes sont prioritaires sur toute préférence esthétique.

---

# Principe 1
# Mobile First

Le smartphone constitue la plateforme principale.

Toutes les interfaces sont conçues d'abord pour :

Android

↓

iPhone

↓

Tablette

↓

Desktop

Les adaptations Desktop ne doivent jamais dégrader l'expérience mobile.

---

# Principe 2
# Clarté avant esthétique

Chaque élément doit être immédiatement compris.

L'utilisateur ne doit jamais réfléchir pour savoir :

où cliquer,

comment contacter,

ou quelle action effectuer.

La compréhension est toujours prioritaire sur l'effet visuel.

---

# Principe 3
# La conversion guide le Design

Le site poursuit un objectif principal :

obtenir une prise de contact.

Chaque écran doit rapprocher le visiteur de cette action.

Les éléments qui n'apportent aucune valeur au parcours utilisateur doivent être supprimés.

---

# Principe 4
# Une seule action principale par écran

Chaque section importante doit présenter un objectif dominant.

Exemples :

Demander un enlèvement.

Appeler immédiatement.

Remplir le formulaire.

Lire les informations.

Les CTA secondaires ne doivent jamais concurrencer le CTA principal.

---

# Principe 5
# Le logo est la référence

L'identité visuelle est construite autour du logo officiel GH Épaviste.

Les composants doivent reprendre son langage graphique :

formes simples,

couleurs sobres,

contrastes forts,

absence d'effets inutiles.

Le Design ne doit jamais donner l'impression d'appartenir à une autre marque.

---

# Principe 6
# Simplicité

Les assistants IA privilégient les interfaces légères.

Éviter :

les éléments décoratifs inutiles,

les animations excessives,

les blocs trop chargés,

les effets visuels gratuits.

La simplicité inspire davantage confiance.

---

# Principe 7
# Cohérence

Deux composants ayant la même fonction doivent avoir le même comportement.

Les utilisateurs ne doivent jamais devoir réapprendre l'interface.

Les boutons, cartes, formulaires et sections utilisent les mêmes conventions sur tout le site.

---

# Principe 8
# Lisibilité

Le texte doit rester parfaitement lisible :

en plein soleil,

sur un smartphone,

sur un écran ancien,

avec un zoom à 200 %.

La lisibilité n'est jamais sacrifiée au profit du style.

---

# Principe 9
# Accessibilité native

Les interfaces sont pensées pour être accessibles dès leur conception.

Les assistants IA ne considèrent jamais l'accessibilité comme une étape supplémentaire.

Elle fait partie intégrante du Design.

---

# Principe 10
# Performance

Chaque élément graphique possède un coût.

Les assistants IA doivent toujours rechercher la solution offrant le meilleur rapport :

Qualité visuelle

↓

Performance

Les composants lourds doivent être évités lorsqu'une alternative plus légère existe.

---

# Principe 11
# Confiance

Le Design doit inspirer immédiatement :

professionnalisme,

transparence,

fiabilité.

Les éléments de réassurance doivent être visibles sans surcharger la page.

---

# Principe 12
# Hiérarchie visuelle

Chaque écran doit guider naturellement le regard.

L'ordre de lecture attendu est :

Logo

↓

Titre principal

↓

Sous-titre

↓

CTA principal

↓

Informations complémentaires

↓

Éléments secondaires

Les assistants IA doivent éviter toute concurrence visuelle entre ces niveaux.

---

# Principe 13
# Espaces respirants

Les espaces vides font partie du Design.

Ils améliorent :

la compréhension,

la lisibilité,

la concentration,

la qualité perçue.

Les assistants IA ne doivent jamais remplir un espace simplement parce qu'il est disponible.

---

# Principe 14
# Uniformité

Tous les composants partagent :

les mêmes rayons,

les mêmes espacements,

les mêmes ombres,

les mêmes animations,

les mêmes transitions,

les mêmes comportements.

Les variations injustifiées sont interdites.

---

# Principe 15
# Durabilité

Le Design System est conçu pour accompagner le projet pendant plusieurs années.

Chaque décision doit rester pertinente lorsque :

de nouvelles fonctionnalités seront ajoutées,

le nombre de pages augmentera,

de nouveaux assistants IA participeront au développement.

---

# Principes interdits

Les assistants IA ne doivent jamais :

Créer plusieurs styles de boutons pour la même fonction.

Utiliser plusieurs palettes concurrentes.

Multiplier les effets d'ombre.

Employer des gradients décoratifs sans justification.

Introduire des animations distrayantes.

Ajouter des composants qui ne répondent à aucun besoin utilisateur.

Sacrifier les performances pour des effets visuels.

---

# Gouvernance

En cas de conflit entre plusieurs solutions graphiques, appliquer l'ordre suivant :

1. Compréhension.

2. Accessibilité.

3. Performance.

4. Cohérence.

5. Conversion.

6. Esthétique.

---

# Cas spécifique GH Épaviste

Les visiteurs arrivent souvent dans une situation urgente.

Le Design doit donc privilégier :

la rapidité de compréhension,

la visibilité du téléphone,

la simplicité du formulaire,

des CTA immédiatement identifiables,

une navigation courte,

des textes directs.

L'utilisateur doit comprendre le service proposé en moins de cinq secondes.

---

# Validation

Avant d'approuver un nouveau composant, les assistants IA vérifient :

✔ Respect du logo.

✔ Respect des couleurs officielles.

✔ Respect du Mobile First.

✔ Respect des principes d'accessibilité.

✔ Respect de la cohérence.

✔ Respect des performances.

✔ Respect des objectifs de conversion.

✔ Respect de la simplicité.

✔ Respect de l'identité GH Épaviste.

---

# Principe final

Le Design System ne cherche pas à impressionner.

Il cherche à rassurer.

Chaque élément graphique doit renforcer la confiance, accélérer la compréhension et faciliter la prise de contact.

L'excellence d'un Design ne se mesure pas au nombre d'effets visuels.

Elle se mesure à la facilité avec laquelle un utilisateur atteint son objectif.

# CONVERSION ENGINEERING FRAMEWORK

## Objectif

Le Conversion Engineering Framework définit la stratégie officielle permettant de transformer un visiteur en prospect qualifié.

Chaque décision de design, de contenu et de développement doit contribuer à réduire les frictions et à faciliter la prise de contact.

La conversion est une conséquence d'une excellente expérience utilisateur.

---

# Philosophie

Les utilisateurs ne viennent pas admirer un site.

Ils viennent résoudre un problème.

Le rôle de GH Épaviste est de leur permettre d'obtenir une solution rapidement.

Chaque élément de l'interface doit participer à cet objectif.

---

# Définition de la conversion

Une conversion est atteinte lorsqu'un utilisateur :

• appelle GH Épaviste ;

• envoie le formulaire ;

• ou réalise toute autre action de contact officiellement définie.

Les clics, les scrolls et le temps passé ne sont pas des objectifs en eux-mêmes.

---

# Les quatre piliers

Toutes les pages reposent sur :

Compréhension

↓

Confiance

↓

Action

↓

Confirmation

Si l'un de ces piliers est faible, la conversion diminue.

---

# Compréhension

En moins de cinq secondes, le visiteur doit comprendre :

Qui intervient.

Quel service est proposé.

Dans quelle zone.

Comment contacter l'entreprise.

Aucune ambiguïté.

---

# Confiance

Le visiteur doit rapidement percevoir :

une entreprise réelle,

des informations cohérentes,

des engagements clairs,

des coordonnées visibles,

une identité professionnelle.

La confiance précède toujours l'action.

---

# Action

Chaque page possède une action principale.

Exemples :

Appeler maintenant.

Demander un enlèvement.

Envoyer une demande.

Les CTA secondaires ne doivent jamais concurrencer cette action.

---

# Confirmation

Après chaque interaction importante :

le système confirme,

explique la suite,

rassure le visiteur.

L'incertitude est réduite au minimum.

---

# Frictions

Les assistants IA doivent identifier et supprimer :

les formulaires trop longs,

les textes inutiles,

les CTA contradictoires,

les informations répétées,

les animations qui ralentissent,

les menus complexes,

les éléments distrayants.

---

# Charge cognitive

Réduire l'effort mental.

Une seule idée principale par section.

Une seule action principale par écran.

Les décisions doivent être évidentes.

---

# CTA

Les CTA utilisent :

un verbe d'action,

une promesse claire,

une forte visibilité.

Exemples :

Appeler maintenant

Demander un enlèvement

Être rappelé rapidement

Jamais :

Continuer

Valider

Envoyer

---

# Placement des CTA

Le CTA principal est présent :

dans le Hero,

après les arguments de confiance,

après les services,

avant le footer.

Sur mobile, il reste facilement accessible.

---

# Téléphone

Le numéro est considéré comme un CTA.

Il doit être :

visible,

cliquable,

lisible,

accessible.

Sur smartphone, le clic lance directement l'application d'appel.

---

# Formulaire

Le formulaire doit être :

court,

compréhensible,

rapide.

Chaque champ doit justifier son existence.

---

# Réassurance

Avant chaque CTA important :

rappeler les bénéfices,

réduire les craintes,

renforcer la crédibilité.

---

# Objections

Les IA doivent anticiper les questions fréquentes.

Exemples :

Y a-t-il des frais ?

Combien de temps ?

Comment cela fonctionne ?

Les réponses sont intégrées naturellement au contenu.

---

# Parcours

Le nombre de clics est réduit.

Le visiteur atteint son objectif avec le moins d'étapes possible.

---

# Micro-conversions

Certaines actions renforcent la progression :

ouverture de la FAQ,

clic sur le téléphone,

consultation des services,

lecture des engagements.

Ces actions ne remplacent pas la conversion principale.

---

# Cohérence

Les règles de conversion sont identiques sur :

Homepage,

Services,

Départements,

Communes,

Contact.

---

# Responsive

La stratégie de conversion est identique.

Seule la disposition change.

Le smartphone reste la priorité.

la rapidité,

la confiance,

la prise de contact.

Les visiteurs recherchent une solution immédiate.

Plus un utilisateur possède de choix,

Les éléments importants doivent être :

faciles à atteindre,

proches du pouce sur smartphone.

## Préambule

GH Épaviste n'est pas simplement un site Internet.

C'est un produit numérique conçu pour résoudre un besoin réel.

Lorsqu'une personne recherche un épaviste, elle se trouve souvent dans une situation où elle souhaite agir rapidement.

Notre responsabilité est de rendre cette démarche simple, compréhensible et fiable.

Chaque décision prise sur ce projet doit contribuer à cet objectif.

---

# Notre mission

Permettre à toute personne recherchant un service d'enlèvement d'épave de trouver rapidement une information claire, de comprendre le service proposé et de pouvoir entrer en contact facilement.

Le produit doit réduire les frictions, faciliter la prise de décision et instaurer un climat de confiance.

---

# Notre vision

Construire une plateforme durable, rapide, accessible et évolutive.

Chaque amélioration doit renforcer la qualité globale du produit plutôt que multiplier les fonctionnalités.

La croissance ne se mesure pas uniquement au nombre de pages ou de composants.

Elle se mesure à la qualité de l'expérience proposée.

---

# Nos valeurs

## L'utilisateur en premier

Nous concevons chaque interface en partant des besoins des utilisateurs.

Les choix techniques existent pour servir cette expérience.

Jamais l'inverse.

---

## La simplicité

Une solution simple est souvent la meilleure.

La complexité n'est acceptée que lorsqu'elle apporte une valeur démontrée.

---

## La confiance

Le produit présente des informations exactes et vérifiables.

Il ne promet jamais ce qui ne peut pas être tenu.

Il représente fidèlement l'activité de GH Épaviste.

---

## La qualité

Chaque détail compte.

La qualité n'est pas une étape finale.

Elle accompagne tout le cycle de vie du produit.

---

## L'amélioration continue

Aucun produit n'est parfait.

Chaque retour, chaque mesure, chaque observation est une opportunité d'amélioration.

---

# Notre manière de concevoir

Nous commençons toujours par comprendre le problème.

Nous observons le parcours utilisateur.

Nous cherchons à supprimer les obstacles avant d'ajouter des fonctionnalités.

Nous privilégions la cohérence plutôt que l'originalité.

Nous préférons un produit robuste à un produit spectaculaire.

---

# Notre manière de développer

Le code est un moyen.

Le produit est la finalité.

Chaque ligne de code doit être justifiée par un bénéfice concret.

Les composants sont conçus pour être réutilisés.

La dette technique est maîtrisée.

Les décisions sont documentées.

# Notre manière de collaborer

Les intelligences artificielles et les développeurs travaillent dans un objectif commun.

La qualité est une responsabilité partagée.

• la performance ;

• l'accessibilité ;
